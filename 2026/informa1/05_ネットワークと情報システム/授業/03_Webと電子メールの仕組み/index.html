    第3時：Webと電子メールの仕組み

    本時の目標

    • WebやメールのようなサービスがTCP/IPのいちばん上の層の約束（HTTP・SMTPなど）として作られ、届け方を下の層に任せていることを説明できる。
    • Webとメールが、クライアントとサーバのやり取りでできていることを、URLやプロトコルと結びつけて説明できる。
    • メールが「相手の端末の電源が切れていても届く」理由を、メールサーバの役割から説明でき、POPとIMAPの違いを使い方と結びつけて説明できる。
    • データ量と通信速度から、転送にかかる時間を求められる。

    キーワード

    用語 説明
    クライアントとサーバ サービスを要求する側（クライアント）と、要求に応えてサービスを提供する側（サーバ）
    WWW（Web） Webページどうしをリンクでつなぎ、世界中から閲覧できるようにした仕組み
    URL Web上の情報の場所を示す住所。プロトコル・ドメイン名・パスなどからなる
    HTTPとHTTPS WebブラウザとWebサーバがやり取りするためのプロトコル。HTTPSは通信を暗号化したもの
    電子メールのプロトコル（SMTP・POP・IMAP） SMTPはメールを送るとき、POPとIMAPはメールを受け取るときに使うプロトコル
    通信速度（bps） 1秒間に送れるデータ量をビットで表したもの。データ量÷通信速度で転送時間が求められる

    準備物・教材

    • 教科書：情報Ⅰ Flex 第5章
    • 授業動画（いちばん上の層だけ決めればよい／クライアントとサーバ／URLの構成とHTTP・HTTPS／メールの送受信とSMTP・POP・IMAP／通信速度と転送時間）
    • スライド（TCP/IPの4階層の図にWebとメールを重ねた図、URLの分解図、Webページを要求して受け取る流れ図、メールの送受信の流れ図）
    • ワークシート（URLの分解、メールの流れ図の穴埋め、POPとIMAPの使い分けの場面）
    • 計算練習プリント（転送時間を求める。例：100MBの動画を100Mbpsで送ると何秒か。バイト→ビットの換算を手順に分けて書く欄を設ける）
    • 単元マップ（前時の続き）

    授業展開

    時間 段階 学習活動 指導上の留意点
    5分 導入 前時の問い「届ける仕組みはできた。その上でWebやメールは何をやり取りしているのか」を確認する。「新しいアプリを作る会社は、ルーティングやIPアドレスの仕組みを自分で作り直す必要があるか」を問う → 必要ない（下の層に任せられる）。続けて「友だちのスマホの電源が切れているときにメールを送ったら、そのメールはどこにあるのか」を問い、予想を書かせる 前時の「役割で分ける」が、アプリを作る側にとって何を楽にしたかに気づかせる。メールの問いは、「相手がいつも受け取れるとは限らない」という、本時のもう1つの問題として扱う
    18分 展開①（動画視聴） 授業動画を視聴する。問題⑦：届ける仕組みの上で、何をどうやり取りするか → いちばん上の層の約束だけを決めればよい。届け方は下の層（TCP/IP）に任せ、サービスごとに「何を頼み、何を返すか」の約束（プロトコル）を決める。①クライアントとサーバ（要求する側と応える側。Webもメールもこの関係でできている）②URLの構成（https:// がプロトコル、www.example.jp がドメイン名で前時のDNSで番号に変わる、その後ろがサーバの中の場所）③HTTP（ブラウザが要求し、サーバがWebページを返す）。HTTPは中身がそのまま流れるので、暗号化したHTTPSが使われる（理由は次時）。問題⑧：相手がいつも受け取れるとは限らない → メールサーバが預かる。SMTPで送り、受け取る側はPOPまたはIMAPで取りに行く。POPは端末に取り込み、IMAPはサーバに置いたまま見る → スマホとPCの両方で同じメールを見たいならIMAP。最後に、通信速度と転送時間（bpsは1秒あたりのビット数。1バイト＝8ビット）を確認する URLの各部分を、前時のプロトコル・ドメイン名・DNSに結びつける。HTTP・SMTP・POP・IMAPが、前時に学んだ層の「いちばん上の層の約束」であることを、4階層の図に重ねて示す
    20分 展開②（活動） ①URLの分解：ふだん見ているWebページのURLを、プロトコル・ドメイン名・パスに分け、ドメイン名が前時のどの仕組みで番号に変わるかを書く。②メールの流れ図：送信者 → 送信側メールサーバ → 受信側メールサーバ → 受信者の図に、SMTP・POP/IMAPを書き入れる。導入の予想と比べる。③計算練習：転送時間を求める（データ量をビットに直す → 通信速度で割る）。1問を全体で手順を追って解く 計算は「①バイトをビットに直す（×8）②通信速度で割る」の手順を板書で固定する。計算を簡単にするため、データ量・通信速度とも1000倍ずつ（1M＝1000k）で統一する。ねらいは計算の正確さではなく、「データはビット単位で流れ、データ量÷通信速度で時間が決まる」という通信の仕組みの理解であることを意識させる
    7分 まとめ 単元マップの表面にWebサーバ・メールサーバ、HTTP/HTTPS・SMTP・POP/IMAPを書き足し、裏面の「分けて任せる」一覧表に本時の問題を書く。第1時の導入で挙げた「困ること」がほぼ解決したことを確認する。次時の問い「分けて任せた結果、自分のデータは、他人が管理するLANやルータを通って届く。その中身は読まれないのか」を示す 「分けて任せる」ことで世界中がつながった一方、データが他人の機器を通るという新しい問題が生まれたことに気づかせ、暗号化の必要性へつなげる

    板書・スライド構成

    1. 前時の問い／本時の問い：アプリを作る会社は、届ける仕組みを作り直す必要があるか
    2. 問題⑦：いちばん上の層の約束だけ決めればよい（4階層の図にWeb・メールを重ねる）
    3. クライアントとサーバ（要求と応答）
    4. URLの分解図（プロトコル／ドメイン名 → DNS／パス）
    5. HTTPとHTTPS（中身がそのまま流れる → 暗号化。理由は次時）
    6. 問題⑧：相手がいつも受け取れるとは限らない → メールサーバが預かる（SMTP → POP/IMAP）
    7. POPとIMAPの使い分け（1台で見る／複数の端末で見る）
    8. 転送時間の計算手順（×8 → ÷通信速度）と例題
    9. 単元マップへの書き足し（表面・裏面）／次時の問い

    本時の評価

    観点 評価方法 内容
    知識・技能 計算練習プリント・小テスト URL・HTTP/HTTPS・SMTP/POP/IMAPの役割を説明でき、転送時間を求められている
    思考・判断・表現 ワークシート・単元マップ（裏面） Webやメールが届け方を下の層に任せていること、メールが相手の端末の状態に関係なく届く理由、POPとIMAPの使い分けを、それぞれ解決した問題と結びつけて説明できている

    備考・メモ

    • 単位はデータ量・通信速度とも1000倍ずつ（1M＝1000k）で統一し、小テスト・単元テストでもそろえる。1024との違いは扱わない。転送時間を計算できることを、通信の仕組み（ビット単位で流れる、量÷速さで時間が決まる）を理解できていることの確認として位置づけるため。
    • 本時で第1〜3時の「世界中のコンピュータどうしでデータをやり取りする」問題が一通り解決する。まとめで残す「データが他人の機器を通る」という問題が、第4時（暗号化と認証の技術）の出発点になる。
