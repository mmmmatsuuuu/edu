    第4時：暗号化と認証の技術

    本時の目標

    • 共通鍵暗号方式・公開鍵暗号方式・電子証明書を、「前の技術で残った問題を次の技術が解決する」という連鎖として説明できる。
    • デジタル署名とSSL/TLSが、それぞれどんな問題（なりすまし・改ざん・盗み見）を解決しているかを説明できる。
    • 本時の技術とファイアウォールが、情報セキュリティの3要素のどれを守っているかを対応づけられる。

    キーワード

    用語 説明
    暗号化と復号 暗号化はデータを第三者に読めない形に変えること。復号は元に戻すこと
    共通鍵暗号方式 暗号化と復号に同じ鍵を使う方式。処理は速いが、鍵を安全に渡すのが難しい
    公開鍵暗号方式 公開鍵で暗号化し、受信者だけが持つ秘密鍵で復号する方式。鍵を安全に渡す問題を解決する
    デジタル署名 送信者が秘密鍵で作る署名。送信者が本人であることと、データが改ざんされていないことを確かめられる
    電子証明書 公開鍵の持ち主が本物であることを、認証局が証明するデータ
    SSL/TLS 通信を暗号化し、通信相手が本物かを確かめるプロトコル。HTTPSで使われる
    ファイアウォール 外部ネットワークとの境目で通信を監視し、許可されていない通信を遮断する仕組み

    準備物・教材

    • 教科書：情報Ⅰ Flex 第5章
    • 授業動画（暗号化と復号／共通鍵暗号と鍵の受け渡しの問題／公開鍵暗号／デジタル署名／電子証明書と認証局／SSL/TLS／ファイアウォール）
    • スライド（「はがき」と「封筒」のたとえ、南京錠のたとえ、問題→解決の連鎖図、3要素との対応表）
    • ワークシート（シーザー暗号の暗号化・復号、問題→解決の連鎖図の穴埋め、3要素との対応表）
    • ブラウザの鍵マークと電子証明書の表示画面（スクリーンショット）
    • 単元マップ（前時の続き）

    授業展開

    時間 段階 学習活動 指導上の留意点
    7分 導入 前時の問い「分けて任せた結果、自分のデータは他人が管理するLANやルータを通って届く。その中身は読まれないのか」を確認する。単元マップの裏面を見て、範囲・データ・経路を分けて任せたからこそ世界中がつながった一方、データは途中の機器の管理者を信頼できないまま届くことを確認する。HTTPは「はがき」のように中身が見える状態で届くことを示す。シーザー暗号（文字を3つずらす）で短い言葉を暗号化・復号し、「鍵（いくつずらすか）を知らないと読めない」ことを体験する 単元01の情報セキュリティの3要素（機密性・完全性・可用性）を一言で思い出させる。本時の技術を最後に3要素と対応づけることを予告する
    18分 展開①（動画視聴） 授業動画を視聴する。問題→解決の連鎖で進める。①盗み見の問題 → 暗号化②共通鍵暗号：同じ鍵で閉めて開ける。速い。しかし「鍵をどうやって相手に渡すか」（ネットで送ると盗まれる）、相手が増えると鍵も増えるという問題が残る③公開鍵暗号：南京錠のたとえ（南京錠は誰でも閉められるが、開けられるのは鍵を持つ本人だけ）。公開鍵で暗号化し、秘密鍵で復号するので、鍵を渡す問題が解決する。しかし処理が遅く、「その公開鍵は本当に相手のものか」という問題が残る④電子証明書：認証局が「この公開鍵はこの相手のもの」と証明する⑤デジタル署名：なりすましと改ざんを確かめる⑥SSL/TLS：公開鍵暗号で共通鍵を安全に渡し、その後は速い共通鍵暗号で通信する（両方の長所を組み合わせる）。HTTPSはこれを使う⑦ファイアウォール：ネットワークの入口で、許可されていない通信を止める 用語を並べずに、必ず「どんな問題が残ったから、次の技術が生まれたか」の順で示す。SSL/TLSで共通鍵暗号と公開鍵暗号が組み合わされることを、連鎖のまとめとして強調する
    18分 展開②（活動） ①連鎖図の完成：「盗み見 → 暗号化 → 鍵をどう渡す？ → 公開鍵暗号 → その鍵は本物？ → 電子証明書」の連鎖図を、空欄を埋めて完成させる。各矢印に「残った問題」を書く。②鍵マークの確認：ブラウザの鍵マークから電子証明書の画面を見て、連鎖図のどこに当たるかを確かめる。③3要素との対応：暗号化・デジタル署名・電子証明書・ファイアウォールが、それぞれ機密性・完全性・可用性のどれを主に守るかを表にまとめ、ペアで理由を説明し合う 連鎖図は単元テストでも使えるよう、自分の言葉で問題を書かせる。3要素との対応は1対1に決まらない場合もあるので、理由を言えることを重視する
    7分 まとめ 単元マップの通信経路の上に、暗号化（SSL/TLS）とファイアウォールを書き足す。次時の問い「ここまでの技術は、社会のどんな仕組みを支えているのか。それがなかったころ、何に困っていたのか」を示す 第1〜4時で単元マップがほぼ完成したことを確認し、次時はその上に乗る「社会の情報システム」を扱うことを伝える

    板書・スライド構成

    1. 前時の問い：分けて任せた結果、データは他人の機器を通る。中身は読まれないのか（はがきと封筒）
    2. シーザー暗号の体験：鍵を知らないと読めない
    3. 問題→解決の連鎖図（盗み見 → 暗号化 → 鍵の受け渡し → 公開鍵暗号 → 鍵は本物か → 電子証明書）
    4. 共通鍵暗号と公開鍵暗号の比較（鍵の数・速さ・鍵の受け渡し）
    5. 南京錠のたとえ（公開鍵＝南京錠、秘密鍵＝その鍵）
    6. デジタル署名：なりすまし・改ざんの確認
    7. SSL/TLS：公開鍵暗号で共通鍵を渡し、共通鍵暗号で通信する
    8. ファイアウォール：入口で止める
    9. 3要素との対応表
    10. 単元マップへの書き足し／次時の問い

    本時の評価

    観点 評価方法 内容
    知識・技能 ワークシート・小テスト 共通鍵暗号・公開鍵暗号・デジタル署名・電子証明書・SSL/TLS・ファイアウォールの役割を説明できている
    思考・判断・表現 連鎖図・3要素との対応表 各技術を「残った問題を次の技術が解決する」流れで説明し、3要素と理由をつけて対応づけられている

    備考・メモ

    • 単元01で扱ったマルウェア・フィッシング・認証方式は、本時では新しく扱わない。3要素との対応づけの中で「単元01の対策と本時の技術が、どう補い合うか」に触れる程度にする。
    • デジタル署名の仕組み（ハッシュ値など）には深入りせず、「秘密鍵で作り、公開鍵で確かめる。だから本人で、改ざんされていないと分かる」という関係を押さえる。
