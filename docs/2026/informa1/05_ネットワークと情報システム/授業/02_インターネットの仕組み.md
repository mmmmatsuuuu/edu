# 第2時：インターネットの仕組み

## 本時の目標

- 機器やメーカーがばらばらでも通じ合える理由を、「役割で層に分け、層の境目の約束（プロトコル）だけをそろえる」という考え方で説明できる。
- IPアドレスのビット数から表せる数を求め、IPv4からIPv6へ移った理由を説明できる。
- ルーティングとDNSを、「全体を知る機器を置かず、分けて任せる」仕組みとして説明できる。

## キーワード

| 用語 | 説明 |
|---|---|
| プロトコル | 通信を行うための約束ごと（手順や形式の取り決め） |
| TCP/IP | インターネットで使われるプロトコルの組み合わせ。役割ごとに4つの階層に分かれている |
| IPアドレス | ネットワーク上の機器を識別する番号。IPv4では32ビット（0〜255の数4つ）で表す |
| IPv4とIPv6 | IPv4は32ビットで約43億通り。足りなくなったため、128ビットのIPv6が使われるようになった |
| ルーティング | ルータが宛先のIPアドレスをもとに、パケットを送る経路を選ぶこと |
| ドメイン名とDNS | ドメイン名は人が覚えやすい名前（例：example.jp）。DNSはドメイン名とIPアドレスを対応させる仕組み |

## 準備物・教材

- 教科書：情報Ⅰ Flex 第5章
- 授業動画（役割で分ける：プロトコルとTCP/IPの4階層／相手を特定する：IPアドレスとIPv6／経路を分けて任せる：ルーティング／名前の管理を分けて任せる：DNS）
- スライド（手紙を送る流れとTCP/IPの4階層の対応図、ルーティングのバケツリレー図、DNSの階層図（ルート → jp → example.jp）、Webページのアドレスを入力してからサーバに届くまでの流れ図）
- **ウォームアップ用ミニプリント**（「nビット＝2ⁿ通り」の表を完成させる。1→2、2→4、… 8→256。8ビットで表せる最大の数）
- 順序カード（「ドメイン名を入力する」「DNSにIPアドレスを問い合わせる」「パケットに宛先のIPアドレスをつける」「ルータが次の相手を選んで転送する」「サーバに届く」など）
- 単元マップ（前時の続き）

## 授業展開

| 時間 | 段階 | 学習活動 | 指導上の留意点 |
|---|---|---|---|
| 8分 | 導入（ウォームアップ） | 前時の問い「分けたLANどうしは機器もメーカーもばらばら。どう話を通じさせ、どう相手を見つけるのか」と、パケット体験の気づき（番号と宛先が必要）を確認する。ミニプリントで「nビット＝2ⁿ通り」の表を完成させ、8ビットで表せる数が256通り（0〜255）であることを確かめる。隣どうしで確認し、1問を全体で解き直す | 前々単元で「nビット＝2ⁿ通り」の正答率が低かったため、口頭確認で済ませず手を動かさせる。ここで求めた「0〜255」が、IPアドレスの各数の範囲になることを後で回収する |
| 18分 | 展開①（動画視聴） | 授業動画を視聴する。**問題③：機器もメーカーもばらばらで、1社が全部を作るわけではない** → **役割で分ける**。通信の仕事を層に分け、層ごとに約束（プロトコル）を決める。手紙にたとえる（内容を書く／封筒に番号をつけて並べ直せるようにする（TCP）／宛先を書いて届ける（IP）／実際に運ぶ）。下の層の中身は自由（有線でもWi-Fiでもよい）で、**境目の約束だけ**をそろえればつながる。だからWi-Fiを有線に替えてもWebの使い方は変わらない。**問題④：世界中から相手をどう特定するか** → 重ならない番号を配る（IPアドレス）。番号を配る仕事も、地域や組織ごとに分けて任せている。IPv4は8ビット×4＝32ビット、約43億通りでは足りなくなった → 128ビットのIPv6。**問題⑤：世界中の経路を、だれが知っているのか** → だれも全部は知らない。各ルータは「次にだれに渡すか」だけを判断する（ルーティング：バケツリレー）。**問題⑥：番号は覚えにくく、世界中の名前と番号の対応表は1台には収まらない** → 名前の管理も階層に分けて任せる（DNS：「.jp」の管理者、「example.jp」の管理者、と分担し、問い合わせを順にたどる） | 4つの問題を、いずれも「問題 → 何を分けたか → 解決」の順で示す。前時のパケット体験（番号と宛先がないと届かない・並べ直せない）を、TCPとIPの役割につなげる。ルーティングとDNSは「全体を知る機器を置かない」という点が共通していることを強調する |
| 17分 | 展開②（活動） | ①ウォームアップの結果を使い、IPv4の各数が0〜255である理由と、32ビットで約43億通りになることを確かめる。IPv6の128ビットでは、32ビットに比べてどれだけ増えるかを「2ⁿ」の考え方で説明する。②**順序カード**を並べ、Webページのアドレスを入力してからサーバに届くまでの流れを完成させる。③**単元マップ**：表面にIPアドレス・ルーティング・DNSサーバを書き足し、裏面の「分けて任せる」一覧表に本時の4つの問題を書く | 順序カードは、並べるだけでなく「なぜこの順番か（名前のままでは届けられないので、先に番号に変える）」を言わせる。前々単元で手順の並べ替えが弱かったため、図と結びつけて確認する |
| 7分 | まとめ | 単元マップの裏面を見て、これまでに分けたもの（範囲・データ・役割・番号・経路・名前の管理）を確認する。第1時の導入で挙げた「困ること」のうち、解決したものに印をつける。次時の問い「届ける仕組みはできた。では、その上でWebやメールは何をやり取りしているのか」を示す | 「プロトコル」は次時以降も出てくる（HTTP・SMTPも、いちばん上の層の約束）ことを予告する |

## 板書・スライド構成

1. 前時の問い／ウォームアップ：nビット＝2ⁿ通りの表
2. 問題③：ばらばらの機器が通じ合うには → 役割で分ける（TCP/IPの4階層と手紙の対応図）
3. 境目の約束だけそろえる（下の層の中身は自由）
4. 問題④：相手の特定 → IPアドレス（8ビット×4＝32ビット、各数は0〜255／約43億通り → IPv6の128ビット）
5. 問題⑤：経路はだれが知る → ルーティング（次の相手に渡すバケツリレー）
6. 問題⑥：名前と番号の対応 → DNS（階層に分けて任せる）
7. Webページのアドレスを入力してからサーバに届くまでの流れ図
8. 単元マップへの書き足し（表面・裏面）／次時の問い

## 本時の評価

| 観点 | 評価方法 | 内容 |
|---|---|---|
| 知識・技能 | ミニプリント・小テスト | IPアドレスのビット数から表せる数を求め、プロトコル・ルーティング・DNSの役割を説明できている |
| 思考・判断・表現 | 順序カード・単元マップ（裏面） | 各技術がどんな問題を解決したかを「何を分けたか」と結びつけて説明し、ドメイン名を入力してからサーバに届くまでの流れを説明できている |

## 備考・メモ

- TCP/IPの4階層の名称（アプリケーション層・トランスポート層・インターネット層・ネットワークインターフェース層）は、名前を覚えることより「なぜ分けるのか（役割分担と、境目の約束だけそろえればよいこと）」を優先する。
- 学校の環境で可能であれば、教師のPCで `nslookup` などを実演し、ドメイン名からIPアドレスが返ってくる様子を見せる（必須ではない）。
