# 第1時：ネットワークの構成

## 本時の目標

- 「世界中のコンピュータどうしでデータをやり取りする」という大きな問題を、小さな問題に分けて考える見方（分けて任せる）を理解する。
- 世界全体を1つのネットワークにできない理由と、LANごとに作ってルータでつなぐ（ネットワークのネットワーク）という解決を説明できる。
- 回線交換方式の問題点と、データを分けて送るパケット交換方式による解決を説明できる。

## キーワード

| 用語 | 説明 |
|---|---|
| ネットワーク | 複数のコンピュータや機器を通信回線でつなぎ、データをやり取りできるようにしたもの |
| LANとWAN | LANは家庭・学校など限られた範囲のネットワーク。WANは離れたLANどうしを結ぶ広い範囲のネットワーク |
| インターネット | 世界中のネットワークを相互につないだ、ネットワークのネットワーク |
| ルータ | 異なるネットワークどうしをつなぎ、データの行き先を判断して転送する機器 |
| 回線交換方式とパケット交換方式 | 回線交換は通信の間、回線を占有する方式（例：昔の固定電話）。パケット交換はデータを小さく分けて送り、回線を共有する方式 |
| パケット | 送るデータを小さく分けたかたまり。宛先などの情報がついている |
| 無線LAN（Wi-Fi） | ケーブルを使わず電波でつなぐLAN。アクセスポイントを通じて接続する |

## 準備物・教材

- 教科書：情報Ⅰ Flex 第5章
- 授業動画（単元の問い／範囲で分ける：LAN・WAN・インターネットとネットワーク機器／データを分ける：回線交換とパケット交換／有線と無線）
- スライド（「世界中を1本の仕組みでつなぐ」想像図、学校のネットワーク構成の簡略図、回線交換とパケット交換の比較図）
- **単元マップ**（A4・1枚。本時から第6時まで使い続ける。表面に「スマホ → アクセスポイント → ルータ → インターネット → サーバ」の枠、裏面に「分けて任せる」一覧表（小さな問題／何を分けたか／解決した技術）の枠を印刷しておく）
- パケット体験用カード（短い文章を5〜6枚に切り分けたもの。番号つきとなしの2セット）

## 授業展開

| 時間 | 段階 | 学習活動 | 指導上の留意点 |
|---|---|---|---|
| 8分 | 導入 | 「今朝からスマホで何をしたか。その情報はどこから来たか」を問い、ほとんどが離れた場所のコンピュータ（サーバ）とのやり取りであることを確認する。単元の問い「**どうすれば、世界中のコンピュータどうしでデータをやり取りできるか**」を示し、「世界中のコンピュータを、1つの仕組み・1つの管理者でつなごうとしたら、何が困るか」をペアで挙げさせる（例：大きすぎて管理できない、みんなが同じ機器をそろえられない、全員が同時に回線を使えない、相手をどう探すか） | 出てきた「困ること」を板書に残し、単元を通してこれらを1つずつ解決していくことを伝える。解決の考え方は「**大きな問題を小さく分け、分けたそれぞれに任せる**」であることを示す |
| 17分 | 展開①（動画視聴） | 授業動画を視聴する。**問題①：世界全体を1つのネットワークにはできない** → **範囲で分ける**。学校・家庭・会社などがそれぞれ自分のLANを作って管理する（中身は有線でもWi-Fiでもよい）。LANどうしはルータでつなぎ、離れたLANを結ぶのがWAN。こうしてつながった全体が、ネットワークのネットワーク＝インターネット。LANの中の機器（スイッチ：LAN内の機器をつなぐ／アクセスポイント：無線の機器をLANにつなぐ）と、LANの出入口のルータの役割を区別する。**問題②：1本の回線を大勢で同時に使えない**（回線交換は通信の間ずっと回線を独占する。少しのデータでも回線が埋まり、途中が切れると止まる） → **データを分ける**。パケット交換は、データを小さく分けて回線を共有し、別の経路でも届けられる。最後に、有線と無線の長所・短所を確認する | どちらの問題も「問題 → 何を分けたか → 解決」の順で示す。インターネットは「最初から1つの計画で作られた」のではなく、「こう考えると、なぜこの形なのかが分かる」という見方として示す |
| 18分 | 展開②（活動） | ①**パケット体験**：ペアの一方が番号なしのカードをばらばらの順に渡し、受け手が元の文章に並べ直す。次に番号つきのカードで同じことを行い、違いを話し合う → 「分けて送るなら、番号と宛先が必要」に気づく（分けたことで生まれた新しい問題）。②**単元マップ（表面）**：学校のネットワーク（Chromebook → アクセスポイント → スイッチ → ルータ → インターネット）を図にかき、学校のLANの範囲を囲む。③**単元マップ（裏面）**：「分けて任せる」一覧表に、本時の2つの問題（範囲で分ける／データを分ける）を書く | パケット体験の気づき（番号と宛先がないと届かない・並べ直せない）を板書に残し、次時の導入で使う。単元マップは毎時書き足すので、余白を残してかかせる |
| 7分 | まとめ | 単元マップを見ながら、ルータ・アクセスポイントが図のどこにあるかを確認する。導入で挙げた「困ること」のうち、本時で解決したものに印をつける。次時の問い「分けたLANどうしは、機器もメーカーもばらばら。どうやって話を通じさせ、世界中から相手を見つけるのか」を示す | 単元マップは毎時持参させる（または教室で保管する） |

## 板書・スライド構成

1. 単元の問い：どうすれば、世界中のコンピュータどうしでデータをやり取りできるか
2. 1つの仕組みで世界中をつなごうとしたら困ること（生徒の意見）
3. 解決の考え方：大きな問題を小さく分け、分けたそれぞれに任せる
4. 問題①：世界全体は1つにできない → 範囲で分ける（LAN・WAN・インターネットの関係図）
5. ネットワーク機器の役割（スイッチ・アクセスポイント：LANの中／ルータ：LANの出入口）
6. 問題②：1本の回線を大勢で使えない → データを分ける（回線交換とパケット交換の比較）
7. 分けたことで生まれた新しい問題：番号と宛先が必要
8. 有線と無線の比較
9. 単元マップへの書き足し／次時の問い

## 備考・メモ

- 単元の軸は「どうすれば、世界中のコンピュータどうしでデータをやり取りできるか」。第1〜3時はこの問いを小さな問題に分けて1つずつ解決し、第4時は「分けて任せたことで生まれた問題」として暗号化を扱う。
- 「分けて任せる」は、プログラミング単元などで扱う「問題の分解」と同じ考え方として紹介してよい。アルゴリズムの用語である「分割統治法」とは呼ばない（同じ形の小さな問題に分けて解く方法を指すため、混同を避ける）。
- 単元マップは本単元の軸になる教材。表面の図には技術の「場所」を、裏面の一覧表には技術が生まれた「理由（何を分けたか）」を書きためる。
