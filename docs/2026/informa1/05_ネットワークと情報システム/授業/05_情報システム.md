# 第5時：情報システム

## 本時の目標

- 身近な情報システム（POSシステム・交通系ICカード・クラウドサービス）について、登場する前にどんな問題があり、どの技術でどう解決したかを説明できる。
- それぞれの事例が、情報システムのどの性質（収集→蓄積→処理→提供の流れ、技術の組み合わせ、クライアントとサーバの関係）をよく表しているかを説明できる。
- 社会がシステムに頼るほど信頼性が重要になる理由と、それを高める工夫（冗長化・誤り検出）を説明できる。

## キーワード

| 用語 | 説明 |
|---|---|
| 情報システム | コンピュータとネットワークを組み合わせて、情報の収集・処理・提供を行う仕組み |
| POSシステム | 商品の販売時点で売上情報を記録・集計するシステム。在庫管理や商品開発に活用される |
| 電子決済（キャッシュレス決済） | 現金を使わず、ICカードやスマートフォンなどで支払う仕組み |
| クラウドサービス | インターネットを通じて、ソフトウェアや保存場所などを必要な分だけ利用できるサービス |
| 冗長化 | 故障に備えて装置やデータを二重にするなどして、システムが止まらないようにする工夫 |
| 誤り検出（パリティチェック） | 通信中にデータが変化していないかを、付け加えた検査用のビットで確かめる方法 |

## 事例の扱い方

各事例を、次の4点で示す。サービスや技術の名前を並べるのではなく、「なかったころの問題」を先に示すことで、当たり前すぎて意識されないシステムの意味を明示する。

| 事例 | ① 登場前 | ② 問題 | ③ 解決（使われている技術） | ④ この事例を扱う理由 |
|---|---|---|---|---|
| POSシステム | レジは金額だけを記録していた。何が売れたかは、店員の記憶や手作業の集計、棚の確認に頼っていた | 「どの商品が、いつ、何個売れたか」が分からない。発注が勘と経験に頼るため、売り切れや売れ残り（廃棄）が起きる。集計に手間がかかる | バーコードを読み取り、商品ごとの販売記録を販売時点で自動で残す（収集）。ネットワークで本部に集め（蓄積）、集計して（処理）、発注・在庫管理・商品開発に使う（提供） | 情報システムの流れ（収集→蓄積→処理→提供）が1つの事例の中でそろって見える。集めたデータを活用する例として、次単元（データベースとデータの活用）に直接つながる |
| 交通系ICカード（電子決済） | 駅では、運賃表を見て切符を買い、改札で駅員が確認していた（のちに自動改札で切符を読み取るようになった） | 券売機に行列ができる。乗り越すと精算が必要になる。小銭の用意や釣り銭の管理に手間がかかる。混雑する改札では、1人に時間をかけられない | カードをかざすだけの無線通信で、一瞬で読み書きする（第1時：無線）。改札機がその場で運賃を計算して残高を書き換え、記録は後からネットワークでセンターに集める（第2時：ネットワーク）。偽造や不正な書き換えを防ぐため、暗号化の技術を使う（第4時） | 「改札を止めずに一瞬で処理する」という厳しい条件を、第1〜4時の技術の組み合わせで満たしている。1つのシステムの中で、これまでの技術がまとめて働いている |
| クラウドサービス | データやソフトウェアは、自分のPCや、会社が自前で用意したサーバに置いていた | PCが壊れるとデータが消える。別の端末からは使えない。会社は利用者が増えるとサーバを買い足し、管理する人も必要になる（使わない時期は余る） | データとソフトウェアをインターネットの向こうのサーバに置き、どの端末からでも使えるようにする（第3時：クライアントとサーバ）。事業者が設備をまとめて管理し、利用者は必要な分だけ使う | 生徒が毎日使っている（Google Classroom・ドライブなど）。第3時のクライアントとサーバの関係が、そのままサービスの形になっている |

## 準備物・教材

- 教科書：情報Ⅰ Flex 第5章
- 授業動画（情報システムとは／POSシステム／交通系ICカード／クラウドサービス／信頼性を高める工夫）。各事例を上の表の①〜④の順で構成する
- スライド（POS導入前後の店舗の比較、改札の今と昔の写真、情報システムの流れ図（収集→蓄積→処理→提供））
- ワークシート（事例ごとの「登場前・問題・解決・使われている技術」の整理表、パリティチェックの練習）
- 大規模なシステム障害のニュース記事（決済・交通・銀行などが止まった事例を1つ。教師が選ぶ）
- 単元マップ（前時の続き）

## 授業展開

| 時間 | 段階 | 学習活動 | 指導上の留意点 |
|---|---|---|---|
| 7分 | 導入 | 前時の問いを確認する。「コンビニの店長になったとして、『昨日、おにぎりが何個売れたか』を、レジの記録が合計金額だけだったら答えられるか」を問いかける。続けて、駅の改札の昔の写真（駅員が切符を確認している）を見せ、今との違いを挙げさせる | 生徒にとって当たり前のシステムに「なかった時代」があったことに気づかせる。本時は、どの事例も「登場前→問題→解決」の順で考えることを伝える |
| 18分 | 展開①（動画視聴） | 授業動画を視聴する。①情報システムとは（収集→蓄積→処理→提供の流れ）②**POSシステム**、③**交通系ICカード**、④**クラウドサービス**を、それぞれ「登場前・問題・解決・使われている技術」の順で見る（上の表）。⑤**信頼性**：社会がシステムに頼るほど、「止まる」ことの影響が大きくなる → 冗長化（二重化・バックアップ）。通信中のノイズで0と1が入れ替わることがある → 誤り検出（パリティチェック） | 各事例で、第1〜4時の技術がどこで使われているかを明示する。POSシステムは「データを集めて活用する」点を強調し、次単元へつなげる |
| 18分 | 展開②（活動） | ①**整理表**：3つの事例について、登場前・問題・解決・使われている技術を整理表にまとめる。「使われている技術」の欄には、単元マップから該当する技術（無線LAN・IPアドレス・クライアントとサーバ・暗号化など）を選んで書く。②**比べる**：ペアで、3つの事例のうち「情報システムの流れ（収集→蓄積→処理→提供）がいちばんよく分かる事例」を選び、理由を説明し合う。③**信頼性**：システム障害のニュースを読み、止まったことで誰が困ったか、冗長化があると何が変わるかを書く。パリティチェックの練習（7ビットのデータの1の個数を偶数にそろえる検査ビットをつけ、1ビット変化したデータを見つける）を1問行う | 整理表は「問題」の欄を具体的に書かせる（「不便だった」ではなく、何がどう困ったか）。パリティチェックは前々単元の2進数とつながることに触れる。計算に深入りせず、「検査用のビットで変化に気づける」ことを押さえる |
| 7分 | まとめ | 単元マップのサーバの先に、本時の情報システム（POS・交通系IC・クラウド）を書き足し、単元マップを完成させる。次単元への問い「POSシステムで集めた大量の販売データは、どう管理し、どう活用するのか」を示す | 次時は単元テストであることを伝え、完成した単元マップを見直しておくよう促す |

## 板書・スライド構成

1. 本時の問い：当たり前のシステムがなかったころ、何に困っていたのか
2. 情報システムの流れ（収集→蓄積→処理→提供）
3. POSシステム：登場前／問題／解決（バーコード・ネットワーク・集計）／扱う理由
4. 交通系ICカード：登場前／問題／解決（無線・ネットワーク・暗号化）／扱う理由
5. クラウドサービス：登場前／問題／解決（クライアントとサーバ）／扱う理由
6. 信頼性：止まると困る → 冗長化／データが変わる → 誤り検出（パリティチェックの例）
7. 単元マップの完成
8. 次単元への問い：集めたデータをどう管理し、どう活用するのか

## 本時の評価

| 観点 | 評価方法 | 内容 |
|---|---|---|
| 知識・技能 | ワークシート・小テスト | 各事例の仕組みと、冗長化・誤り検出の役割を説明できている |
| 思考・判断・表現 | 整理表・ペアでの説明 | 事例ごとに登場前の問題と解決の仕組みを、第1〜4時の技術と関連づけて説明できている。情報システムの流れがよく分かる事例を、理由をつけて選べている |
| 主体的に学習に取り組む態度 | 授業への参加状況 | 身近なシステムを、登場した理由や仕組みと結びつけて捉えようとしている |

## 備考・メモ

- 事例は3つに絞る。ATM・ネット通販・電子マネーなどほかの事例を加える場合も、同じ4点（登場前・問題・解決・扱う理由）で示せるものに限る。名前だけの紹介はしない。
- 交通系ICカードの「改札機がその場で処理し、記録は後からセンターに集める」という説明は、仕組みを単純化したもの。細部は事業者によって異なる。
- POSシステムの事例は、次単元（データベースとデータの活用）の導入で再び使う。
